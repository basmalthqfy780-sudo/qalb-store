# قالب — Qalb · متجر قوالب معرض الأعمال + السيرة الذاتية

متجر واجهة-أمامية يبيع **قوالب مواقع بورتفوليو شخصية** و**سير ذاتية**، و**حزمًا تجمع الاثنين بهوية واحدة**.
الفكرة المحورية: ملفك المهني كله (الموقع + الـCV + الخطاب) يخرج من نفس متغيرات التصميم — وتعاين الموقع
**حيةً داخل إطار متصفح** قبل الشراء.

**التقنيات**: React 18 + Vite 6 + Tailwind CSS v4 (بدون مكتبة UI جاهزة) + React Router. ثنائي اللغة
`ar ⇄ en` مع تبديل `RTL/LTR` لحظيًا.

**النسخة**: `1.2.0` · موسومة `v1.2.0`. ما في كل نسخة مُثبَّت سطرًا سطرًا في [`CHANGELOG.md`](CHANGELOG.md) —
مصدره مخرجات `npm test` والوسوم، لا وصف مكتوب من الذاكرة.

---

## التشغيل

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # إنتاج dist/
npm run preview    # معاينة نسخة الإنتاج
npm test           # ٣٢ مجموعة / ٣٦٥ فحصًا: تصيير ٢٠ مسارًا (٩٦ توقعًا) + ١٢ مجموعة تفاعلية (٢٦٩ فحصًا) في jsdom،
                   # ثم ٧٢ فحصًا لخادم اللوحة والتسليم (npm run test:api يشغّله وحده)
npm run lint       # eslint (بما فيها قواعد مترجِم react-hooks) — صفر مشكلة
npm run format     # prettier؛ وnpm run format:check للتحقق فقط

# إضافيات اختيارية
npm run gen:seo    # public/robots.txt + sitemap.xml + og-cover.png (قبل كل build تعمل تلقائيًا)
npm run gen:fonts  # تنزيل الخطوط إلى public/fonts وتوليد src/fonts.css
npm run gen:deliverables  # يولّد حزم القوالب الخمس عشرة إلى dist-deliverables/ (للاستضافة اليدوية)
npm run api        # خدمة الطلبات: node server/worker.js على :8787
```

| ٢٩ ملف woff2 مودَعة بلا نص ترخيص | `public/fonts/OFL-*.txt` الثلاثة منسوخة حرفيًا من مصادرها + `public/fonts/README.md` يوثّق العائلة والمصدر (OFL تُلزم بإبقاء النص مع الخط) |

| محمّل `.env` مكرور في `seo.mjs` و`worker.js` | وحدة واحدة `scripts/dotenv.mjs` يستوردها الاثنان، مع فحص في `npm test` يرفض رجوع النسخة المكرورة |

اصطادت القواعد الجديدة أخطاء حقيقية، وأُصلحت في مصدرها لا بالتسكين: `setState` داخل effect في شريط
التنقل والكتالوج (صارت المزامنة أثناء الرندر، وحجم الصفحة مشتقًّا من مفتاح الفلاتر بلا جولة رسم زائدة)،
ومكوّنان كانا يُولَّدان داخل الرندر (`Contacts` في `ResumePreview` و`ProjectCard` في `SitePreview` —
صارتا دالَّتَي رسم بنفس الشجرة وهوية ثابتة)، و`flags` صارت مثبَّتة بـ`useMemo`، وستّة `catch {}` صارت موثّقة.

## الوضع المحلي مقابل الخادم (لا شيء مطلوب للتشغيل)

كل ما يمس «الطلبات» يمرّ من ملف واحد: `src/api/index.js` بأربعة دوال
(`submitOrder`, `fetchOrder`, `listOrders`, `verifyKey`).

| الوضع             | كيف                                           | السلوك                                                                        |
| ----------------- | --------------------------------------------- | ----------------------------------------------------------------------------- |
| `local` (افتراضي) | بدون إعداد                                    | يولّد `QALB-…` ومفتاح الترخيص، ويخزّن في `localStorage` تحت `qalb.orders.v1`  |
| `rest`            | `VITE_QALB_API=rest` + `VITE_QALB_API_BASE=…` | `POST /orders`، `GET /orders/:id`، `GET /orders?email=`، `GET /licences/:key` |

- `/track` و`/licence` هما الواجهة الحيّة لدالتَي `listOrders`/`verifyKey` — نفس العقد في الوضعين.
- صفحة إتمام الشراء تعرض نقطة صغيرة تبيّن الوضع (ذهبية = تجريبي، خضراء = متصل).
- فشل الشبكة لا يفرّغ السلة: يظهر `role="alert"` + زر «إعادة المحاولة».
- `/order?id=QALB-…` يعيد بناء الإيصال من الخادم — تصلح كرابط بريد.
- الخادم يعيد حساب المجاميع من `src/data/templates.js` ويرفض أي `total` لا يطابق (±0.50 ر.س)،
  ويحترم `Idempotency-Key`. التفاصيل والعقد في `server/README.md`، والمخطط في `server/schema.sql`.
- الدفع يبقى محاكى: لا مفاتيح، لا بوابة. لربط Stripe/salla راجع قسم «الدفع الحقيقي» في نفس الملف.

## التسليم: ملفات حقيقية، ورابط موقّع لكل طلب على حدة

الحزم ليست «قريبًا» ولا ملفات فارغة: `src/data/deliverable.js` يولّد لكل قالب **حزمة كاملة**
من بياناته نفسها — ١٣ ملفًا للسيرة (`resume.html` للطباعة A4، `resume.md` يلصق في Word/Docs،
`cover-letter.md`، `content/profile.json`، `scripts/check-ats.mjs` الذي يعطي نسبة ATS حقيقية)،
و٢٠–٢٤ لموقع أو حزمة (`index.html` + `styles.css` ثنائي اللغة RTL/LTR يعملان من القرص،
`server.mjs` للتشغيل بلا أي حزم، `projects/*.md` لكل عمل، `vercel.json`/`netlify.toml` للنشر،
و`framework/` فيه الأقسام نفسها مكوّنات Astro/Next مع دليل نقل). كل حزمة تحمل `LICENSE.txt`
برخصة **مقعد واحد** باسم المشتري ومفتاحه، وسطر تتبّع أعلى كل ملف نصي فيه رقم الطلب —
فإعادة التوزيع تقود إلى صاحبها، وهي مكتوبة في الرخصة صراحة.

|                       | ماذا يحدث                                                                                                                                                                                                                                                                     |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`local` (افتراضي)** | صفحة الإيصال تبني الأرشيف داخل متصفحك (ZIP مكتوب في `src/data/zip.js` بلا أي اعتماد خارجي) وتنزّله باسم `qalb-<id>-<order>.zip`. لا خادم هنا، والصفبة تقول ذلك صراحة: احفظ الملف قبل إغلاق التبويب                                                                            |
| **`rest`**            | `GET /download/<id>?order=…&key=…` يتحقق من الطلب ومن مفتاح الرخصة (مقارنة timing-safe) ومن أن القالب **داخل ذلك الطلب**، ثم يعيد ٣٠٢ إلى `/dl/<token>`: رابط HMAC صالح ١٠ دقائق ويُسخدم **مرة واحدة**، ومسجَّل في `server/downloads.jsonl`، ومحدود بعدد محاولات لكل عنوان IP |

- لا شيء يُخزَّن في `public/`: ملف ثابت هناك = رابط عام يُنسخ ويعمل عند الجميع بلا طلب ولا رخصة. الحزمة تُبنى لحظة الطلب في الذاكرة فقط.
- إن فضّلت الاستضافة بنفسك: `npm run gen:deliverables` يولّد نسخ مراجعة (بلا اسم مشتري) إلى `dist-deliverables/`، ثم ضع روابطها في اللوحة — الواجهة تتعامل مع الشكلين.
- الربط آليّ: كل قالب في `src/data/templates.js` يحمل `download: '/download/<id>'` منذ البداية، فتظهر في اللوحة شارة
  «تسليم موقّع لكل طلب على حدة» بجانب الصفوف الخمسة عشر بلا أن يُكتب رابط واحد باليد — ولا زرّ يفتحه من اللوحة، لأن الرابط
  يحتاج رقم طلب المشتري ومفتاح رخصته؛ الإيصال هو من يبني الرابط الموقّع.
- الفحص يغطي الطرفين: `npm test` يفتح الإيصال في jsdom ويقرأ **بايتات** الأرشيف الناتج (`PK` + قائمة الملفّات + رقم الطلب داخل `LICENSE.txt`)، و`npm run test:api` يشغّل الخادم الحقيقية: تنزيل كامل، محاولة ثانية ٤٠٣، مفتاح خاطئ ٤٠٣، مجهول ٤٠١، قالب مُخفى ٤٠٤، فيضان ٤٢٩.

## تخصيص القالب ببيانات المشتري (اختياري)

عند صفحة المنتج وفي خطوة الدفع يوجد صندوق «تخصيص القالب قبل التنزيل»: خمس حقول اختيارية
(الاسم الكامل، المسمى الوظيفي، البريد، رقم الجوال، الرابط الرئيسي) ونبذة عن أعمالك. ما يُكتب فيها
يُطبع داخل ملفات الحزمة نفسها لحظة التوليد — لا في الإيصال وحده:

| الحقل          | أين يظهر في الحزمة                                                                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------------------- |
| الاسم الكامل   | `<h1>` و`<title>` و`og:title` وترويسة الموقع والتذييل، وعنوان `resume.md`، وتذييل خطاب التقديم                        |
| المسمى الوظيفي | سطر «المسمى · المدينة» في السيرة، وتحت الاسم في ترويسة الموقع                                                         |
| البريد والجوال | سطر التواصل في `resume.html`/`resume.md` و`content/profile.json`                                                      |
| الرابط الرئيسي | `host` — يُختُز إلى مضيف نظيف (`https://x.dev/a?b=1` ← `x.dev`) ويُطبع نصًا لا كرابط، فلا يُزرع رابط نيابة عن المشتري |
| نبذة عن أعمالك | `blurb`: «عني» في الموقع، و«ملخص مهني» في السيرة، وجملة التعريف في خطاب التقديم؛ وتُختم بنقطة إن لم تكن مختومة        |

**القواعد الصارمة** (`sanitizePersonal` في `src/data/deliverable.js` — هي نفسها التي يستدعيها
`server/worker.js` عند الحفظ، فلا يختلف ما يُخزَّن عمّا يُولَّد):

- لا شيء افتراضًا: الصندوق مغلق، والحقل الفارغ في الدفع يُؤخذ من بيانات الفاتورة، وما يبقى فارغًا يحتفظ بنص القالب التجريبي.
- سقف لكل حقل: ‏80 للاسم، 90 للمسمى، 160 للبريد والرابط، 40 للجوال، 700 للنبذة — وما يتجاوزه يُبتَر لا يُطبع.
- حقل يحوي `<` أو `>` يُرفَض كلّه ويُترَك نص القالب، ولا يُعرض مشوَّهًا؛ وتظهر على الحقل نفسه عبارة «لن يُطبع هذا الحقل» بدل مفاجأة بعد التنزيل.
- البريد يجب أن يطابق نموذج بريد، والجوال أن يبدأ برقم ويحوي أرقامًا فقط، والرابط أن يكون مضيفًا سليمًا؛ وإلا يُهمَل الحقل بصمت في الملفات مع تنبيه في الواجهة.
- النبذة تُسطَّر في سطر واحد وتُختم بنقطة؛ ومحارف التحكم تُستبدل بمسافة (محرف تحكّم واحد يفسد سطر التتبّع أعلى الحزمة).
- تُحفظ القيم منقّاة داخل الطلب (`order.personalize`)، فتُقرأ عند كل رابط تنزيل جديد، ولا تُصدَّر في CSV اللوحة (يُصدَّر علم `personalized=yes` فقط) — بيانات المشتري لا تتنقل بين الملفات.

الملفات كلها تبقى قابلة للتعديل بعد التنزيل: نفس القيم في `content/profile.json`، والموقع والسيرة يقرآنها مباشرة.

- الفحص: مجموعة `personalisation · typed once, printed in every file` ‏(٤٥ فحصًا) تغطي المنظِّف والحقول والحزمة والواجهة ومقطع الدفع بالكامل حتى الإيصال؛ و`npm run test:api` يفتح أرشيف تنزيل حقيقي من الخادم ويقرأ `content/profile.json` و`resume.html` منه للتأكد أن الاسم المكتوب مطبوع داخل الملف المُسلَّم، وأن حقلًا مرفوضًا لم يصل إليه شيئًا منه.

## لوحة الإدارة (Admin)

تُفتح من `/admin`، ومن عمود «الشركة» في التذييل (رابط «لوحة الإدارة»). فيها أربعة أقسام:
**النظرة العامة** (دخل، عدد الطلبات الناجحة، متوسط السلة، ضريبة ١٥٪ المستخرجة، آخر ٣٠ يومًا، الأكثر مبيعًا)،
**المنتجات** (تصفير السعر، ربط رابط التنزيل — عام أو `/download/<id>` محمي، إخفاء/إظهار، منتج مخصّص جديد، تعديل النصوص والفئة)،
**الطلبات** (مع تصدير CSV حقيقي من بيانات الطلبات نفسها)، و**الصلاحيات** (إضافة مسؤول، تغيير كلمة سر، حذف — مع رفض حذف الحساب الموثّق حاليًا أو آخر مالك).

| النقطة                                                | السلوك الفعلي                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| من أين تأتي الأرقام                                   | لا شيء مكتوب يدويًا: الدخل والطلبات تُحسب من سجلّ الطلبات نفسه (`src/data/stats.js`) — `qalb.orders.v1` في الوضع المحلي، و`server/orders.jsonl` في وضع الخادم. نفس الوحدة يستوردها الخادم، فلا يوجد حسابان مختلفان.                                                                                                                                                                                                                                                                                                             |
| سعر الأكثر مبيعًا                                     | كل سطر طلب يُختم عليه السعر الذي حوسب فعلًا، فيبقى إيراد المنتج ما دُفع وقت البيع لا سعر اليوم؛ وتجمع أعمدة «الأكثر مبيعًا» فيساوي الدخل الإجمالي. الطلبات الأقدم من هذه القاعدة تُحسب بالسعر الحالي، نصًا.                                                                                                                                                                                                                                                                                                                     |
| نصّ «أضف إلى السلة» و«اشتراك» كان يختفي فوق زرّ فاتح  | قواعد الـ reset في `src/index.css` كانت مكتوبة **خارج `@layer`**، و`button { color: inherit }` و`* { border-color }` كانت تتغلّبان على كل أداة Tailwind (طبقات CSS تُحسم قبل الـ specificity). صارتا داخل `@layer base`: الاسم ظهر، و`border-brand/40` و`focus:border-brand/50` و٣٦ عنوانًا بـ`font-extrabold` تعمل كما كُتبت. فحص `css · cascade layers` يرفض أي عنصر بلا طبقة يلوّن النص، ويقيس تباين WCAG فعلًا: dark 6.7–16.4 وlight 5.1–17.8 على أسطحها، مع تصحيح حبر الوضع الفاتح إلى `#04140d` بدل أبيض 3.4:1 على الأخضر |

| حدود الخطأ كانت تعرض «إعادة المحاولة» لصفحة لا تُصلَح | خطأ مثل `does not provide an export named …` أو `Failed to fetch dynamically imported module` ليس عطل تصيير: إعادة المحاولة تعيد استيراد نفس الوحدات المعطوبة. `src/lib/load-error.js` يميّزه، فيُعاد تحميل المستند **مرة واحدة** تلقائيًا (محميّ بـ`sessionStorage` حتى لا يدور في حلقة)، وإن بقي الخلل يظهر زرّ «إعادة تحميل الصفحة بالكامل» بدل زرّ إعادة المحاولة.                                                                                                                                                          |

| محركات البحث                                          | `/admin` تحمل `robots: noindex,follow` وممنوعة في `robots.txt`، فلا تُفهرس ولا تُعدّ صفحة عامة.                                                                                                                                                                                                                                                                                                                                                                                                                                 |

- `npm test` يشغّل ٣٥ فحصًا على اللوحة نفسها في jsdom (بوابة، تهيئة المالك، رفض كلمة سر خاطئة،
  تعديل السعر ووصوله إلى السلة، الإخفاء ومنعه من الدفع، إضافة مسؤول، منع حذف النفس، تسجيل الخروج)،
  و`npm run test:api` يشغّل ٧٢ فحصًا على واجهة الخادم الحقيقية (الإدارة + التسليم الموقّع) (تشغّل `server/worker.js` فعلًا داخل مجلد

  فلو أردت فهرسة منتج مخصّص أضفه إلى الملف ثم `npm run gen:seo`.

## أصول الظهور والخطوط

- `scripts/seo.mjs` (يعمل قبل كل `build`) يولّد `robots.txt` و`sitemap.xml` (٢٠ رابطًا) وبطاقة
  `og-cover.png` مرسومة برمجيًا بـ Pillow (`scripts/og-cover.py`) — بدون صور مخزّنة في المستودع.
  يولّد أيضًا **بطاقة لكل منتج** في `public/og/` (تُقرأ من نفس `src/data/templates.js`)؛ لو لم تتوفّر
  Pillow يُتخطّى الرسم وتبقى البطاقات السابقة — لا يفشل البناء لهذا السبب.
- `public/_redirects` (`/* /index.html 200`) يُبقي الروابط العميقة تعمل على Netlify وCloudflare Pages؛
  Vercel يكتشف ذلك تلقائيًا لمشاريع Vite.
  `SITE_URL=https://mydomain.com npm run gen:seo` يعيد توليدها بنطاقك، أو ضع
  `SITE_URL=https://mydomain.com` في `.env` مرة واحدة فتُقرأ في كل `npm run build`.
- البريد الرسمي `qalb@qalb.store` هو الافتراضي في `src/data/contact.js`، ويظهر في الواجهات
  والإيصالات و`JSON-LD/Organization`. لتغييره مؤقتًا اضبط `VITE_QALB_MAIL` في `.env` بدل تعديل الملفات واحدًا واحدًا.
- `src/components/Seo.jsx` يضبط لكل مسار: `title`، `description`، `og:*` (بما فيها `og:locale`)،
  `canonical`، و`robots: noindex,follow` على السلة/الدفع/الإيصال، و**JSON-LD**:
  `WebSite` + `Organization` + `SearchAction` في الرئيسية، `ItemList` في الكتالوج،
  و`Product` + `Offer` + `AggregateRating` في صفحة القالب.
- الخطوط مستضافة محليًا (`public/fonts` + `src/fonts.css`) بلا طلبات خارجية؛ `npm run gen:fonts` يحدّثها،
  ونصّ ترخيص SIL OFL 1.1 لكل عائلة منسوخ حرفيًا بجانبها (`public/fonts/OFL-*.txt` و`public/fonts/README.md`).

## ملاحظات تنفيذية

- **التحجيم التلقائي**: المكوّنان يرسمان على «عرض تصميم» ثابت (640px للسيرة، 1280/768/420 للموقع) ثم
  `transform: scale()` محسوب من عرض الحاوية عبر `ResizeObserver` — لذا المعاينة نفسها تتغيّر مع النوافذ.
- **الضريبة**: الأسعار شاملة ١٥٪ وتُستخرج في الملخص (لا تُضاف فوقه) كما هو معتاد في المتاجر السعودية.
- **RTL**: مسافات منطقية دائمًا (`ps-/pe-/ms-/me-/start-/end-`)، والأرقام داخل `.num` (tabular-nums + LTR).
  لا نعتمد على ترتيب الكلاسات المتضادة؛ اتجاهات الجرّ تتحدد من `lang` في JS.
- **الوصول**: `focus-visible`، `aria-label/pressed/expanded`، `role="dialog"` + `aria-modal` + `inert` للخلفية،
  مصيدة Tab، منطقة إشعارات `role="status"`، و`prefers-reduced-motion`.
- **الأرقام**: كل الأسعار تُنسّق عبر `dec()` (أرقام لاتارية، فواصل إنجليزية) حتى لا تتكسر المعادلات عند قراءة النص.
- **حدود الخطأ**: `ErrorBoundary` حول `<Suspense>` في `App.jsx` بمفتاح `pathname#attempt`؛ «إعادة
  المحاولة» تزيد `attempt` فتُعاد تركيب الشجرة (يكفي لأخطاء الحزم والبيانات العابرة)، وأي تنقّل يمسح
  الشاشة القديمة وحده. الأخطاء الرامية من `effect` تمرّ من الطريق نفسه.
- **الجودة في CI**: `npm run lint` + `npm run format:check` + `npm test` + `npm run build` في
  `.github/workflows/ci.yml`؛ قواعد `react-hooks` الحديثة تكشف `setState` داخل effect وتوليد المكوّنات
  داخل الرندر، وهي التي دلّت على المواضع أعلاه.
- **الصفحة الأولى**: مجموعة خاصة تتأكد أن شريط المنصات بلا أي كلاس حركة، وأن الشرائح الطافية أعلى من
  كل بطاقة معاينة — تقرأ `style.zIndex` الحقيقية ولا تفترض رقمًا، فلو نمت المروحة لكشف ذلك.
- **الصفحة الأولى**: مجموعة خاصة تقرأ `src/index.css` نفسه — تتأكد أن `marquee` اختفى من المصدر، وأن
  `prefers-reduced-motion` يضبط `animation-iteration-count: 1`، وأن الشرائح الطافية أعلى من كل بطاقة معاينة.

- **اختبار jsdom**: `tests/smoke.mjs` ينتظر استقرار DOM بعد حلّ الحزم الكسولة عبر `settle()` (يكتشف هيكل
  `<Suspense>` ولا يقرأه كصفحة جاهزة) — وهذا بالضبط ما كشف مشكلة الانتظار الثابت القديم.
- **الكوبونات**: `SALE25` · `WELCOME10` · `QALB30`.
- الدفع محاكى بالكامل: لا بوابة دفع، ولا عملية شحن فعلية.
